## 1. What this project is

`oil_gas_tools` is a self-directed oil & gas education project. Two halves:

1. **A six-notebook Python analytical suite** tracking the weekly data an energy
   analyst watches — inventories, spreads, storage, curve shape, LNG exports, rigs.
2. **A written curriculum** covering the value chain from upstream geology through
   downstream petrochemicals.

The owner (Michael, GitHub `MikeC92`) is learning by building. **This shapes how to
help:** he has asked to type code manually rather than receive finished files, for the
slower pace that forces thinking about structure. Hand code over in reviewable pieces
with explanation. Don't silently rewrite notebooks end-to-end — propose, explain, let
him apply. Ask before any large refactor.

That rule has one carve-out he set himself: once a transformation is well understood,
repeating it across the remaining tools is review work, not learning work, and Claude
Code should do it with diffs he approves.

### Path convention

Notebooks live in `notebooks/` and resolve the root one level up:

```python
PROJECT_ROOT = Path.cwd().parent
sys.path.insert(0, str(PROJECT_ROOT))
DATA_DIR   = PROJECT_ROOT / "data"
CHARTS_DIR = PROJECT_ROOT / "charts"
```

`data/` and `charts/` are gitignored — regenerated by running the notebooks.

### Editing a module while a notebook is open

Python caches imports, so editing `chart_style.py` does nothing to a running kernel.
Every notebook's imports cell carries:

```python
%load_ext autoreload
%autoreload 2
```

Without it, a style change needs a kernel restart, which means re-downloading
everything to see a color move.

## 4. Secrets and notebook outputs

`config.py` at the project root holds a live EIA API key. **Gitignored. Never
committed.**

**Notebook outputs are a secret-leak surface, not just diff bloat.** Cell 1 of Tool 2
once printed `API_KEY[:6]`, and because outputs were committed, six characters of a
live key sat in the public repo. The key has been rotated and the line now prints a
presence check. The standing rules that came out of it:

- Never print any part of a credential, not even a prefix.
- **Clear outputs before committing.** (`nbstripout` is on the backlog to automate it.)
- Before any commit touching the root:

```bash
git status --short | grep -E "config\.py|data/|charts/|pycache"
```

Empty output is the only acceptable result.

| 6 | `rig_count_tracker` | Baker Hughes rigs by basin | Manual XLSB | Weekly (Fri) |

**Tool 2 is the reference implementation** for the chart style and the data-honesty
patterns. When reworking Tools 3–6, follow it.

### Cross-tool dependencies

Tools read each other's CSVs from `data/`. **Always load the newest by modification
time, never alphabetically:**

```python
files = sorted(glob.glob(str(DATA_DIR / "crude_inventory_*.csv")),
               key=lambda f: os.path.getmtime(f))
```

Alphabetical sorting puts "May" after "June" (M > J). That bug made Tool 2 display
$90 WTI against a $69 market. Fixed in Tools 2, 4, 5, 6 — don't reintroduce it.

New output filenames are ISO-dated (`wti_brent_monitor_2026-10-09.png`) so they sort
correctly in the first place.

### Commentary logs

Each tool appends a timestamped entry to a log in `data/`. Append, never overwrite —
the series of readings is the point.

## 7. Charts

All charting goes through `chart_style.py`. Never set a font size, paste a hex, or
call `tight_layout()` in a notebook.

```python
import chart_style as cs
cs.apply_style()          # before any figure is created
```

The rules, in full in `docs/chart_style.md`:

- **Hue = commodity**, fixed project-wide. WTI blue, Brent vermillion, Henry Hub
  green, TTF sky, JKM rose.
- **Line style = kind of series.** `PRIMARY` / `DERIVED` / `PROJECTED` / `CONTEXT`.
  A 50-day average of WTI keeps WTI's blue and takes the dash.
- **Never `twinx()`.** Two panels, or index to a common base.
- **Shading needs both ends.** `regime_span()` raises if either is missing;
  `event_marker()` draws a rule with no fill.
- **Labels go in a reserved right margin**, via `label_series()`, never on the data.
- **Same xlim on every panel before labelling**, or stacked panels drift apart.
- **`finish(fig, path, tight=False)`** for GridSpec figures with explicit `hspace`.
- **figsize follows data density** and stays in the notebook — 13in for 750 daily
  points, ~9.5in for 42 weekly bars.
- After editing `chart_style.py`, run `python chart_style.py` (its self-test).

## 8. Known fragile points — check these before debugging anything else

### 8a. M2 futures tickers go stale when the front month rolls (Tools 2, 4)

`CL=F` and `NG=F` are continuous; the M2 legs are explicit contracts and must be
advanced manually.

**The tell: M1 and M2 print identical prices and the spread is $0.00.**

```python
for label, tkr in [("WTI", "CL=F"), ("NG", "NG=F")]:
    info = yf.Ticker(tkr).info
    print(f"{label}: {info.get('shortName','N/A')} "
          f"| underlying: {info.get('underlyingExchangeSymbol','N/A')} "
          f"| expires: {info.get('expireIsoDate','N/A')[:10]}")
```

Month codes: `F`Jan `G`Feb `H`Mar `J`Apr `K`May `M`Jun `N`Jul `Q`Aug `U`Sep `V`Oct
`X`Nov `Z`Dec. Also in `notebooks/contract_month_codes`.

Tool 2 identifies contracts **by price, not metadata** — `underlyingExchangeSymbol` is
unreliable. Its candidate list needs a quarterly refresh.

### 8b. EIA facet codes change without notice

Working codes today:

```python
# gas storage
ROUTE = "/natural-gas/stor/wkly/data/"
process = "SWO"                        # not "SAT"
regions = {"us_total": "R48", "east": "R31", "midwest": "R32",
           "south_total": "R33", "mountain": "R34", "pacific": "R35"}

# LNG exports — old /natural-gas/move/lnge/ returns HTTP 400
ROUTE     = "/natural-gas/move/expc/data/"
facets    = {"duoarea": ["NUS-Z00"], "process": ["ENG"]}
frequency = "monthly"                  # weekly no longer published
```

When a call returns no rows, **query the `/facet/{id}/` endpoints — don't guess.**

### 8c. Tool 6 — Baker Hughes is manual by design

Auto-download was removed deliberately (the hardcoded UUID URL served April data in
August without erroring). Download the XLSB by hand into `data/`; `_cache_is_stale()`
detects it by mtime. **Do not re-add auto-download.**

### 8d. Tool 1 only exports the current year

`df_current_us` merges the current year onto a static seasonal band keyed by
week-of-year, so its CSV holds ~52 rows. Tool 2's inventory↔price correlation
therefore has ~42 overlapping weeks and an effective n of ~9 after the 4-week return
overlap — no statistical power at all. **Fixing this means a rolling seasonal z-score
across full history in Tool 1.** On the backlog.

### 8e. Unit conversions that have bitten

TTF is EUR/MWh. To reach USD/MMBtu you **multiply** by 0.29307:

```python
MWH_PER_MMBTU = 0.29307
df["ttf_usd_mmbtu"] = df[raw_col] * EUR_USD * MWH_PER_MMBTU
# sanity: 46 EUR/MWh × 1.18 × 0.293 ≈ $15.90/MMBtu
```

Dividing produced $187/MMBtu. Every conversion carries its dimensional analysis in a
comment and a sanity-check print.

Crack spread (Tool 7): `(2 × RBOB + 1 × ULSD) ÷ 3 − WTI`, products at 42 gal/bbl.

### 8f. Stale notebook output looks like current data

Tool 2 prints a loud `STALENESS WARNING` when the cached dashboard price diverges from
the live quote by more than $5. **When a number looks wrong, restart the kernel and
run all before investigating the code.**

### 8g. SVG authoring

Escape bare `&` as `&amp;`. No `<style>` blocks — CSS overrides presentation
attributes, so contrast fixes silently revert, and Word/PowerPoint drop them on
import. Include `xmlns` or nothing renders.

## 9. Data honesty patterns (from Tool 2, apply everywhere)

**Don't compute a relationship from a filled value.** Tool 2 outer-merges WTI and
Brent across two exchange calendars, then computes the spread **only where both legs
genuinely traded** — 4,779 of 4,977 sessions. The 198 one-sided days stay NaN. Prices
are forward-filled afterward for display continuity, never before.

**Don't rank across a regime change.** The spread percentile starts at 2016, because
the December 2015 export-ban repeal changed what the Brent–WTI spread *is*.

**Don't report a correlation without a sample size.** Fisher-z intervals, with the
effective n adjusted for overlapping forward-return windows. If the interval spans
zero, the verdict is "no signal" — not "inconclusive", which implies the data said
something murky rather than nothing.

**Date events explicitly.** An `EVENTS` dict, not a price-threshold heuristic that
silently relocates as data changes.

## 10. Diagnose before assuming

1. Query the API's own metadata before trusting a facet code.
2. Compare cached values against a live quote before trusting a cache.
3. Identify a futures contract by price, not metadata.
4. Restart the kernel before trusting on-screen output.
5. When his data disagrees with an outside source, check whether the *outside source*
   is wrong. (TradingView showed a $5.03 Brent–WTI spread against the notebook's
   $11.91; the notebook was right — ICE Brent rolls ~3 weeks ahead of NYMEX WTI.)

Guards live inside the notebooks so failures surface loudly instead of propagating
into charts and commentary.
