## 1. What this project is

`oil_gas_tools` is a self-directed oil & gas education project. Two halves:

1. **A six-notebook Python analytical suite** that tracks the same weekly data an
   energy analyst watches — inventories, spreads, storage, curve shape, LNG exports,
   rig counts.
2. **A written curriculum** (reference guide + diagram atlas) covering the value chain
   from upstream geology through downstream petrochemicals.

The owner (Michael, GitHub `MikeC92`) is learning by building. **This matters for how
to help:** he has explicitly asked to type code manually rather than receive finished
files, for the slower pace that forces thinking about structure and design. Default to
explaining and handing over code in reviewable pieces, not to silently editing
notebooks end-to-end. Ask before doing a large refactor for him.

### Path convention

Every notebook lives in `notebooks/` and resolves the project root one level up:

```python
PROJECT_ROOT = Path.cwd().parent
DATA_DIR     = PROJECT_ROOT / "data"
CHARTS_DIR   = PROJECT_ROOT / "charts"
```

`data/` and `charts/` are gitignored — they are regenerated by running the notebooks.

### Secrets

`config.py` at the project root holds a live EIA API key:

```python
EIA_API_KEY = "..."
```

**It is gitignored and must never be committed.** This has already been a near-miss:
the ignore file was once misnamed `gitgnore` (missing the second `i`), so git ignored
nothing and `config.py` was staged. Before any commit that touches the root directory,
run:

```bash
git status --short | grep -E "config\.py|data/|charts/|pycache"
```

Empty output is the only acceptable result. Nothing has ever been pushed with the key.

### Cross-tool dependencies

Tools read each other's CSV output from `data/`. Tool 2 reads Tool 1's inventory
export; Tools 4/5/6 read from each other. **Always load the newest file by
modification time, never alphabetically:**

```python
# WRONG — alphabetical sorting puts May after June (M > J)
files = sorted(glob.glob(str(DATA_DIR / "crude_inventory_*.csv")))

# RIGHT
files = sorted(
    glob.glob(str(DATA_DIR / "crude_inventory_*.csv")),
    key=lambda f: os.path.getmtime(f)
)
```

This bug caused Tool 2 to display $90 WTI while the market was at $69. It has been
fixed in Tools 2, 4, 5 and 6 — do not reintroduce it in Tool 7.

### Commentary logs

Each tool's final cell appends a timestamped record of its run to a log file in
`data/`. These are the written trail of what the tools said week over week — do not
overwrite them, always append.

## 5. Known fragile points — check these before debugging anything else

### 5a. Tool 4 / Tool 2 — M2 futures tickers go stale when the front month rolls

`CL=F` and `NG=F` are continuous front-month contracts. The M2 legs are **explicit**
contracts and must be advanced manually each time the front month rolls:

```python
WTI_M1_TICKER = "CL=F"
WTI_M2_TICKER = "CLM26.NYM"   # must be exactly ONE month ahead of CL=F's underlying
NG_M1_TICKER  = "NG=F"
NG_M2_TICKER  = "NGM26.NYM"
```

**The tell that they are misaligned: M1 and M2 print identical prices and the spread
is $0.00.** Run the diagnostic cell every session:

```python
for label, tkr in [("WTI", "CL=F"), ("NG", "NG=F")]:
    info = yf.Ticker(tkr).info
    print(f"{label}: {info.get('shortName','N/A')}  "
          f"| underlying: {info.get('underlyingExchangeSymbol','N/A')}  "
          f"| expires: {info.get('expireIsoDate','N/A')[:10]}")
```

CME month codes: `F`=Jan `G`=Feb `H`=Mar `J`=Apr `K`=May `M`=Jun `N`=Jul `Q`=Aug
`U`=Sep `V`=Oct `X`=Nov `Z`=Dec. Also in `notebooks/contract_month_codes`.

In Tool 2, contracts are identified **by price, not metadata** — yfinance's
`underlyingExchangeSymbol` is unreliable. `identify_contract()` downloads candidates
and matches the one whose close is within tolerance of the continuous contract.

### 5b. EIA facet codes change without notice

Routes and facet codes have silently broken more than once. The gas storage codes that
work today:

```python
ROUTE = "/natural-gas/stor/wkly/data/"
process = "SWO"                        # not "SAT"
regions = {"us_total": "R48", "east": "R31", "midwest": "R32",
           "south_total": "R33", "mountain": "R34", "pacific": "R35"}
```

LNG exports moved and lost weekly frequency:

```python
# DEAD: /natural-gas/move/lnge/   → HTTP 400
ROUTE     = "/natural-gas/move/expc/data/"
facets    = {"duoarea": ["NUS-Z00"], "process": ["ENG"]}
frequency = "monthly"                  # weekly no longer published
```

**When an EIA call returns no rows, do not guess new codes.** Query the metadata
endpoints (`/facet/{id}/`) and sample live records to confirm what exists.

### 5c. Tool 6 — Baker Hughes is manual by design

Auto-download was removed at the owner's request. The hardcoded UUID URL serves a
stale file (it once returned April data in August). The workflow is: download the XLSB
by hand, drop it in `data/`, and the notebook detects it:

```python
HEADER_ROW = 10                # long-format parse
def _cache_is_stale() -> bool:
    if not WEEKLY_COMBINED_CACHE.exists():  return True
    if not MONTHLY_COMBINED_CACHE.exists(): return True
    if not MANUAL_FALLBACK.exists():        return False
    return MANUAL_FALLBACK.stat().st_mtime > WEEKLY_COMBINED_CACHE.stat().st_mtime
```

Archive and current files overlap Jan 2024–Aug 2025; the notebook tags each row with
`_source` and drops archive rows whose dates appear in the current file.

### 5d. Unit conversions that have bitten

TTF is quoted in EUR/MWh. To reach USD/MMBtu you **multiply** by 0.29307
(MWh per MMBtu), not divide:

```python
MWH_PER_MMBTU = 0.29307
df["ttf_usd_mmbtu"] = df[raw_col] * EUR_USD * MWH_PER_MMBTU
# sanity check: 46 EUR/MWh × 1.18 × 0.293 ≈ $15.90/MMBtu
```

Dividing produced $187/MMBtu. When adding a conversion, write the dimensional analysis
in a comment and include a sanity-check print.

Crack spread (3-2-1), for Tool 7: `(2 × RBOB + 1 × ULSD) ÷ 3 − WTI`, with products
converted from $/gal to $/bbl at 42 gal/bbl.

### 5e. Stale notebook output is a real failure mode

Saved VS Code cell outputs look like current data. Tool 2 now prints a loud warning
when the cached dashboard price diverges from the live quote:

```python
if abs(current_wti - combined_wti) > 5:
    print("!" * 58)
    print("  STALENESS WARNING")
```

When a number looks wrong, **restart the kernel and run all before investigating the
code.**

### 5f. SVG authoring rules

- Escape bare `&` as `&amp;` ("F&D", "G&A" broke a parse).
- Never use `<style>` blocks: CSS rules override presentation attributes, so contrast
  fixes silently revert. All styling is inline as attributes, which also makes the
  files portable into Word, PowerPoint and LibreOffice.
- Include the `xmlns` namespace or nothing renders.

## 6. Diagnose before assuming

The pattern that has repeatedly been the difference between a real fix and a wasted
hour:

1. Query the API's own metadata before trusting a facet code.
2. Compare cached values against a live quote before trusting a cache.
3. Identify a futures contract by its price, not its metadata label.
4. Restart the kernel before trusting on-screen output.
5. When the owner's data disagrees with an outside source, check whether the *outside
   source* is the one mixing things up. (TradingView showed a $5.03 Brent–WTI spread
   against the notebook's $11.91; the notebook was right — ICE Brent rolls ~3 weeks
   ahead of NYMEX WTI, so TradingView was comparing different delivery months.)

Defensive guards live in the notebooks themselves — staleness warnings,
contract-alignment checks, auto-stale cache detection — so these failures surface
loudly instead of propagating into charts and commentary logs.
